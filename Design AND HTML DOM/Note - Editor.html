Executive Summary

This document outlines the transition plan from our current monolithic backend architecture to an event-driven microservices model. The primary driver for this change is the need for independent scaling of the PaymentProcessing and UserManagement domains.

Current Limitations

  • Tight coupling between deployment cycles.
  • Shared database bottlenecks during peak load (Black Friday, End of Month).
  • Difficult to onboard new engineers to a 2M+ LOC codebase.

Proposed Architecture

We will introduce Apache Kafka as the central event bus. Services will communicate asynchronously by publishing and subscribing to domain-specific topics.

// Example Event Schema (UserCreated)
{
  "eventId": "evt_01H1X9...",
  "eventType": "UserCreated",
  "timestamp": "2023-10-27T10:00:00Z",
  "payload": {
    "userId": "usr_9982",
    "email": "newuser@example.com",
    "region": "US-EAST-1"
  }
}

The NotificationService will subscribe to the UserCreated topic to trigger welcome emails, completely decoupled from the main user registration flow.

Migration Phases

  • Phase 1: Deploy Kafka cluster and implement event publishing in the monolith (Shadow Mode).
  • Phase 2: Extract NotificationService as the first pilot consumer.
  • Phase 3: Break out PaymentProcessing.
